Resource Cleanup

After completing testing and evaluation, clean up the resources created for this workshop.

Follow the order below and select only resources belonging to the workshop.

1. Prepare for Cleanup

Save:

  • Configuration and test screenshots from sections 5.3 through 5.8.
  • Query results and evaluation findings.
  • Any EC2 or log data that must be retained.

Terminating an EC2 instance is irreversible. Deleting a log group removes its stored log data.

Use US East (N. Virginia) — us-east-1 for regional resources.

Verify the cleanup scope:

Resource Name or ID
EC2 instance aws-network-workshop-web
Instance ID i-0ae6186e1e003f511
VPC aws-network-workshop-vpc
VPC ID vpc-0a695d2b618b79ee5
Security group aws-network-workshop-web-sg
Log group /workshop/network/flowlogs
Metric filter rejected-tcp-8080
Alarm aws-network-workshop-rejected-8080
Dashboard aws-network-workshop-dashboard
SNS topic aws-network-workshop-alerts
IAM role workshop-flowlogs-role

If resources were recreated during the workshop, verify their current IDs before deletion.

2. Delete the CloudWatch Alarm and Dashboard

2.1. Delete the Alarm

Open:

CloudWatch → Alarms

  1. Find aws-network-workshop-rejected-8080.
  2. Select the correct alarm.
  3. Choose Actions → Delete.
  4. Confirm deletion.
  5. Refresh the list to verify.

2.2. Delete the Dashboard

Open:

CloudWatch → Dashboards

  1. Select aws-network-workshop-dashboard.
  2. Choose Delete.
  3. Confirm deletion.
  4. Refresh and search for the exact name to verify.

Deleting the dashboard does not delete its source resources. Continue with the following steps.

3. Delete the VPC Flow Log

Open:

VPC → Your VPCs → aws-network-workshop-vpc → Flow logs

Verify the VPC ID:

vpc-0a695d2b618b79ee5

Then:

  1. Select the workshop flow log targeting /workshop/network/flowlogs.
  2. Choose Actions → Delete flow logs.
  3. Enter the confirmation text requested by the dialog.
  4. Choose Delete.
  5. Refresh the list.

Collection can take several minutes to stop after deletion. Continue cleaning up EC2 and the VPC before deleting the destination log group.

Deleting a flow log does not delete existing data from CloudWatch Logs.

4. Terminate the EC2 Instance

Open:

EC2 → Instances

Select:

aws-network-workshop-web
i-0ae6186e1e003f511

Before terminating it, open Storage and record the attached Volume IDs for the next step.

Then:

  1. Select the instance.
  2. Choose Instance state → Terminate (delete) instance.
  3. Verify the selected instance.
  4. Choose Terminate (delete) to confirm.
  5. Wait for the state to become Terminated.

Remove any Running-only filter to view the terminated instance.

A terminated instance can remain visible temporarily. No additional termination action is required once its state is Terminated.

Screenshot 01: Capture the instance name, Instance ID and Terminated state.

5. Check Remaining EBS Volumes

Open:

EC2 → Elastic Block Store → Volumes

Search using the Volume IDs recorded earlier.

  • Volumes configured for deletion on termination may already have been deleted.
  • Inspect any remaining workshop volumes and their attachments.
  • Delete only volumes identified as workshop resources and in the Available state.

To delete a volume:

  1. Select the correct volume.
  2. Choose Actions → Delete volume.
  3. Enter the requested confirmation text.
  4. Confirm deletion.

If a volume remains in-use, investigate its attachment and the instance termination status before proceeding.

6. Delete the VPC and Network Components

After EC2 termination and release of its dependencies, open:

VPC → Your VPCs

  1. Select aws-network-workshop-vpc.
  2. Verify ID vpc-0a695d2b618b79ee5.
  3. Choose Actions → Delete VPC.
  4. Review the associated resources listed for deletion.
  5. Verify that they belong to the workshop VPC.
  6. Enter the confirmation text and choose Delete.

The VPC Console can delete associated subnets, route tables, the internet gateway and security groups as listed in its deletion dialog.

If dependencies block deletion, investigate the listed resources. Remove the appropriate workshop dependencies and retry.

Refresh and search for the VPC name or ID after deletion.

Screenshot 02: Capture the success message or the filtered VPC list showing no matching workshop VPC.

7. Delete the Metric Filter and Log Group

After the flow log has been deleted and delivery has stopped, open:

CloudWatch → Logs → Log Management → /workshop/network/flowlogs

7.1. Delete the Metric Filter

  1. Open Metric filters.
  2. Select rejected-tcp-8080.
  3. Choose Delete and confirm.

7.2. Delete the Log Group

  1. Return to the log group list.
  2. Select /workshop/network/flowlogs.
  3. Choose Actions → Delete log group.
  4. Complete the confirmation.
  5. Refresh and search for the exact name to verify.

Deleting the log group removes its stored log events.

CloudWatch metrics cannot be deleted directly. Historical metric data may remain visible after its publishing sources are removed.

Screenshot 03: Capture the search for /workshop/network/flowlogs showing no matching group.

8. Delete the SNS Subscription and Topic

Open:

Amazon SNS → Topics → aws-network-workshop-alerts

Delete the Confirmed subscriptions belonging to the workshop topic first.

Then:

  1. Return to Topics.
  2. Select aws-network-workshop-alerts.
  3. Choose Delete.
  4. Enter delete me if requested.
  5. Confirm and refresh the list.

Associated subscriptions are deleted asynchronously with the topic. Pending-confirmation subscriptions can remain visible temporarily and cannot be manually deleted through the usual subscription deletion operation.

Screenshot 04: Capture the topic list filtered by the workshop name with no matching topic.

9. Delete the Flow Logs IAM Role

After the flow log is deleted and the role is no longer used by other resources, open:

IAM → Roles

  1. Find workshop-flowlogs-role.
  2. Select the correct role.
  3. Choose Delete.
  4. Review the confirmation information.
  5. Enter the role name if requested.
  6. Confirm deletion.

Deleting a role through the IAM Console also deletes its inline policies. The role’s WorkshopFlowLogsPublish policy is therefore removed with it.

If a separate AllowPassWorkshopFlowLogsRole inline policy was created on the IAM user specifically for this workshop, remove that policy after completing cleanup.

Screenshot 05: Capture the Roles list searched for workshop-flowlogs-role with no matching role.

10. Check Additional Resources

If an Elastic IP address was allocated specifically for the workshop, open:

EC2 → Elastic IPs

After identifying the correct workshop address and verifying that it is no longer associated with a resource, choose:

Actions → Release Elastic IP addresses → Release

If additional snapshots, AMIs or saved queries were created specifically for the workshop, inventory them and determine which should be deleted or intentionally retained.

Document any resources intentionally retained.

11. Completion Checklist

Verify resources using their workshop names and IDs:

  • The alarm is deleted.
  • The dashboard is deleted.
  • The VPC flow log is deleted.
  • The EC2 instance is Terminated.
  • Workshop EBS volumes are checked and handled appropriately.
  • The VPC and associated network components are deleted.
  • The metric filter and log group are deleted.
  • The SNS topic is deleted and its subscriptions are checked.
  • The Flow Logs IAM role is deleted.
  • Any workshop-specific PassRole policy is handled.
  • Additional resources are checked and retained items documented.
  • Cleanup evidence screenshots are saved.
