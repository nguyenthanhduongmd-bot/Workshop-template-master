Testing and Validating the Monitoring System

This section tests EC2 connectivity and validates the monitoring process from VPC Flow Logs through CloudWatch to Amazon SNS.

The following scenarios are used:

Scenario Expected result
Access HTTP port 80 Successful connection and a working web page
Connect to TCP port 8080 Failed connection and a matching REJECT flow log record

A matching log record increases the CloudWatch metric. The alarm evaluates the metric against its configured threshold and sends an SNS notification when it transitions to ALARM.

1. Check the Prerequisites

Use US East (N. Virginia) — us-east-1.

Verify the resources configured in section 5.4:

Resource Name
EC2 instance aws-network-workshop-web
Security group aws-network-workshop-web-sg
Log group /workshop/network/flowlogs
Metric filter rejected-tcp-8080
Metric namespace Workshop/Network
Metric name Rejected8080Flows
CloudWatch alarm aws-network-workshop-rejected-8080
SNS topic aws-network-workshop-alerts

The instance must be Running. Its security groups must allow HTTP port 80 from the test client’s public IP address while keeping port 8080 blocked.

The examples use these addresses:

Address Value
EC2 public IPv4 98.92.170.157
EC2 private IPv4 10.10.1.130
Test client public IP 1.55.6.233

Check the current addresses before testing. Update the examples and filter if any address has changed.

Check the test client’s public IP at:

https://checkip.amazonaws.com/

In the metric filter:

  • srcaddr must match the test client’s public IP without /32.
  • dstaddr must match the EC2 private IPv4 address.

The SNS email subscription must be confirmed. If the alarm is already in ALARM from an earlier test, stop generating test traffic and wait for it to return to OK before starting a new test.

2. Test HTTP Port 80

From the test client’s browser, open:

http://98.92.170.157

Enter the http:// scheme explicitly.

The expected result is the AWS Network Workshop page or the Nginx page served by the instance.

A successful response confirms that HTTP connectivity from the test client to the application is working.

3. Test TCP Port 8080

Open Windows PowerShell on the test client.

If you are using Command Prompt, enter the following command first:

powershell

When the prompt starts with PS, run:

Get-Date
Test-NetConnection -ComputerName 98.92.170.157 -Port 8080

Wait for the command to finish and inspect TcpTestSucceeded.

Expected result:

TcpTestSucceeded : False

Repeat the test two or three more times if needed to generate traffic.

Record the test time so that you can compare it with the flow logs, metric data and alarm history.

Verify the failed connection against a matching REJECT record in the next step.

4. Verify the REJECT Flow Log Record

In the AWS Console:

  1. Open CloudWatch.
  2. Choose Logs → Log Management.
  3. Open /workshop/network/flowlogs.
  4. Select Log streams.
  5. Choose Search all log streams.
  6. Select the 1h time range.

Enter this event filter:

[version, accountid, interfaceid, srcaddr = "1.55.6.233", dstaddr = "10.10.1.130", srcport, dstport = 8080, protocol = 6, packets, bytes, start, end, action = "REJECT", logstatus = "OK"]

Replace the IP addresses if the current configuration differs.

Flow Logs require time to aggregate and deliver records. Delivery to CloudWatch typically takes about five minutes and may take longer. Choose Refresh to check for new records.

Expand a matching event using the arrow beside its timestamp.

Verify these fields:

Field Expected value
srcaddr Test client’s public IP
dstaddr EC2 private IPv4
dstport 8080
protocol 6, representing TCP
action REJECT
logstatus OK

Use a record from the current test period. In the default flow log format, incoming traffic on the EC2 network interface uses its private IPv4 address as the destination.

Vietnam time is UTC plus seven hours.

5. Check the CloudWatch Metric

In CloudWatch, open:

Metrics → Classic metrics

Under Browse, select:

Workshop/Network → Metrics with no dimensions

Select Rejected8080Flows, then open Graphed metrics.

Configure:

Setting Value
Statistic Sum
Period 5 minutes
Time range 1h

If the graph uses Average, change it to Sum to match the alarm configuration.

Choose Refresh and hover over a data point from the test period.

The expected result is a value of 1 or greater.

This metric counts matching log records. The number of connection attempts does not necessarily equal the metric value because Flow Logs aggregate traffic into records.

Metric filters process new data after creation and do not backfill existing logs.

6. Check the CloudWatch Alarm

Open:

CloudWatch → Alarms → aws-network-workshop-rejected-8080

Verify:

Setting Value
Namespace Workshop/Network
Metric name Rejected8080Flows
Statistic Sum
Period 5 minutes
Threshold >= 1
Datapoints to alarm 1 out of 1
Missing data treatment Treat missing data as good
Actions Enabled

When the data satisfies the configured condition, the expected state is In alarm.

Open History and compare the transition time with the test time.

If the alarm has already returned to OK, use the ALARM transition recorded in History to verify the earlier alert.

An OK state can be affected by missing data treatment. Compare the logs, metric and email notification to validate the complete process.

7. Verify the Amazon SNS Email

Open the mailbox subscribed to aws-network-workshop-alerts.

Find the email containing:

aws-network-workshop-rejected-8080

Verify:

  • Alarm name.
  • New state: ALARM.
  • Notification time.
  • Reason for the state change.

If the email has not arrived:

  1. Check the Spam or Junk folder.
  2. Verify that the subscription is confirmed.
  3. Check that the alarm action targets the correct SNS topic.
  4. Verify that the SNS access policy permits CloudWatch publishing.
  5. Inspect the alarm History for the action execution result.

SNS does not send a new email for every connection attempt while the alarm remains in ALARM. A relevant state transition is required to trigger a new notification.

8. Completion Criteria

Check each item after verifying and saving its evidence:

  • HTTP port 80 is accessible.
  • TCP port 8080 connection fails.
  • A REJECT record matches the test addresses, port and time.
  • Rejected8080Flows has a Sum value of at least 1.
  • The alarm transitions to ALARM during the test.
  • The SNS alert email is received.
