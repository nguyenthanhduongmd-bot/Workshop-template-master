Dashboard and Network Log Analysis

In this section, we build a CloudWatch dashboard that brings network monitoring information together on one screen.

The dashboard contains three components:

Component Purpose
Rejected8080Flows graph Monitor rejected port 8080 flow records over time
Alarm status widget Display the alarm’s current state
ACCEPT/REJECT table Summarize flow records by action and destination port

We also use CloudWatch Logs Insights to analyze VPC Flow Logs and add the query results to the dashboard.

1. Prerequisites

Use US East (N. Virginia) — us-east-1 when selecting the workshop metrics and logs.

Verify the following resources:

Resource Value
Log group /workshop/network/flowlogs
Metric namespace Workshop/Network
Metric name Rejected8080Flows
Alarm aws-network-workshop-rejected-8080

Test data from section 5.5 is required to populate the graph and query results.

The sample query uses:

Address Value
Test client’s public IP 1.55.6.233
EC2 private IPv4 10.10.1.130

Update the query if either address has changed.

2. Create a CloudWatch Dashboard

  1. Open CloudWatch.
  2. Choose Dashboards in the navigation pane.
  3. If the navigation pane is hidden, open it using the ☰ icon.
  4. Choose Create dashboard.
  5. Enter:
aws-network-workshop-dashboard
  1. Choose Create dashboard.

The console opens the widget configuration dialog for the first dashboard component.

3. Add the Rejected8080Flows Graph

In Add widget, select:

Setting Value
Data sources types CloudWatch
Data type Metrics
Preferred experience Metrics Console
Widget type Line

Choose Next.

In the metric selector:

  1. Open Browse.
  2. Select Workshop/Network.
  3. Choose Metrics with no dimensions, if displayed.
  4. Select Rejected8080Flows.
  5. Open Graphed metrics.

Configure:

Setting Value
Statistic Sum
Period 5 minutes
Time range 3h, or a range containing the test

If the statistic is Average, change it to Sum. This displays the total value for each five-minute period and matches the alarm configuration.

Screenshot 01: Capture the metric configuration showing Rejected8080Flows, Sum and a five-minute period.

Choose Create widget, then Save dashboard.

4. Add the Alarm Status Widget

On the dashboard:

  1. Choose Add widget or the + icon.
  2. Keep CloudWatch as the data source.
  3. Under Data type, choose Alarms, beside Metrics and Logs.
  4. Select Alarm status.
  5. Choose Next, if displayed.
  6. Find and select:
aws-network-workshop-rejected-8080
  1. Complete the dialog using Create widget or Add to dashboard, as displayed.
  2. Choose Save dashboard.

The widget displays the alarm’s current state:

State Meaning
OK The alarm is not breaching under its configured evaluation settings
ALARM The alarm is in its alert state
INSUFFICIENT_DATA There is insufficient data for evaluation

The state changes with the evaluated data. Selecting a historical dashboard time range does not make this widget display a historical alarm state.

Screenshot 02: Capture the alarm widget showing its name and current state.

5. Analyze ACCEPT and REJECT Records

In the CloudWatch navigation pane, open:

Logs → Log Analytics

Log Analytics brings together log analysis capabilities, including Logs Insights.

5.1. Select the Query Scope

Under Query scope:

  1. Choose All beside Log group.
  2. Select:
/workshop/network/flowlogs
  1. Keep Log class = Standard.
  2. Select 3h, or use Custom to include the test period from section 5.5.

Use Logs Insights QL. The default query containing fields, sort and limit in this interface already uses this language.

5.2. Enter the Query

In the new interface, keep the first line beginning with SOURCE, if present. Replace the query from the fields line onward with:

fields srcAddr, dstAddr, dstPort, protocol, action, logStatus
| filter srcAddr = "1.55.6.233"
    and dstAddr = "10.10.1.130"
    and protocol = 6
    and logStatus = "OK"
| filter dstPort = 80 or dstPort = 8080
| stats count(*) as FlowRecords by action, dstPort
| sort dstPort asc

This query:

  • Filters traffic from the test client’s public IP to the EC2 private IP.
  • Selects TCP records with an OK logging status.
  • Limits destination ports to 80 and 8080.
  • Groups records by action and destination port.
  • Counts the records in each group.

Choose Run or Run query.

5.3. Interpret the Results

The results contain:

Column Meaning
action ACCEPT or REJECT
dstPort Destination port
FlowRecords Matching record count within the selected time range

When corresponding test traffic exists, the results can include ACCEPT on port 80 and REJECT on port 8080.

FlowRecords counts flow log records, rather than page refreshes or individual packets.

If no results appear, check:

  • The selected log group.
  • Whether the time range includes the test.
  • Both IP addresses in the query.
  • Whether Flow Logs have delivered the records.

Screenshot 03: Capture the selected log group, query text and results table.

6. Add the Query Results to the Dashboard

After the query completes successfully:

  1. Choose Add to dashboard.
  2. Select:
aws-network-workshop-dashboard
  1. Choose the Table widget type.
  2. Enter the widget name:
ACCEPT and REJECT by port
  1. Choose Add to dashboard.
  2. Return to the dashboard and choose Save dashboard.

The query table summarizes records across the selected time range. The metric graph shows individual five-minute periods and monitors only rejected port 8080 traffic.

7. Arrange and Verify the Dashboard

Open:

CloudWatch → Dashboards → aws-network-workshop-dashboard

Arrange the components:

  • Rejected8080Flows graph at the top.
  • Alarm status widget beside the graph.
  • ACCEPT and REJECT by port table below.

Drag a widget corner to resize it and drag its title area to reposition it.

Select a time range containing the test and choose Refresh. Choose Save dashboard after changing the layout.

Verify that the dashboard displays:

  1. Metric data in the graph.
  2. The alarm name and current state.
  3. The ACCEPT/REJECT results table.

Screenshot 04: Capture the full dashboard, including its name and all three widgets.

8. Completion Criteria

  • The aws-network-workshop-dashboard dashboard is created and saved.
  • The graph uses Rejected8080Flows.
  • The statistic is Sum and the period is five minutes.
  • The alarm widget displays the correct name and current state.
  • The Logs Insights query returns appropriate data.
  • The results table is added to the dashboard.
  • The required evidence screenshots are captured.
