5.2. Preparation

5.2. Preparation

Introduction

Before deploying the Network Automation and Monitoring system on Amazon Web Services (AWS), we need to prepare the necessary environment, configure our AWS account, and become familiar with the AWS services used throughout this workshop.

Proper preparation helps ensure that the deployment process runs smoothly, reduces configuration errors, and provides a consistent environment for network monitoring and automation.

In this workshop, we will use the AWS Management Console to configure and manage AWS resources. The main services include Amazon VPC, Amazon EC2, AWS Identity and Access Management (IAM), Amazon CloudWatch, VPC Flow Logs, and Amazon Simple Notification Service (SNS).

Objectives

After completing this section, you will be able to:

  • Access and navigate the AWS Management Console.
  • Select the appropriate AWS Region.
  • Understand the main AWS services used in this workshop.
  • Check IAM permissions and security settings.
  • Prepare the environment for VPC and EC2 deployment.
  • Access Amazon CloudWatch and Amazon SNS.
  • Configure AWS Budgets to monitor estimated costs.

5.2.1. Prepare an AWS Account

Step 1: Access the AWS Website

First, open your web browser and visit the official AWS website:

AWS Website: https://aws.amazon.com/

If you do not have an AWS account, click Create an AWS Account to begin the registration process.

If you already have an account, select Sign In to the Console.

Figure 5.2.1. AWS official website.

Step 2: Create an AWS Account

To create an AWS account, follow these steps:

  1. Click Create an AWS Account.
  2. Enter your email address.
  3. Provide a name for your AWS account.
  4. Complete the account verification process.
  5. Enter the required contact information.
  6. Provide a valid payment method if requested.
  7. Complete identity verification.
  8. Select an available support plan and finish registration.

AWS offers free usage allowances or credits for eligible accounts. However, not all AWS services are free, and usage beyond applicable limits may incur charges.

Figure 5.2.2. AWS account registration interface.

Step 3: Sign In to AWS Management Console

After successfully creating your account:

  1. Open https://console.aws.amazon.com/.
  2. Select the appropriate sign-in method.
  3. Enter your account credentials.
  4. Complete multi-factor authentication if required.
  5. Access the AWS Management Console.

The AWS Management Console provides a centralized interface for managing cloud resources, monitoring services, and configuring AWS infrastructure.

Figure 5.2.3. AWS Management Console after signing in.

5.2.2. Select the AWS Region

Step 1: Understand AWS Regions

An AWS Region is a geographical area where AWS operates cloud infrastructure.

Each Region consists of multiple Availability Zones (AZs), which help improve application availability and fault tolerance.

For this workshop, we will use the following Region:

Configuration Value
Region Name Asia Pacific (Singapore)
Region Code ap-southeast-1
Deployment Platform AWS Management Console

Using the same Region throughout the workshop helps simplify resource management and ensures that regional services can interact correctly.

Step 2: Change the AWS Region

Follow these steps:

  1. Sign in to the AWS Management Console.
  2. Locate the Region selector in the upper-right corner.
  3. Click the currently selected Region.
  4. Find Asia Pacific (Singapore).
  5. Select Asia Pacific (Singapore).
  6. Verify that the Region is set to ap-southeast-1.

Figure 5.2.4. Selecting the Asia Pacific (Singapore) Region.

Note: Regional resources such as VPC, EC2, CloudWatch, and SNS should be configured in the selected Region. IAM is a global AWS service.

5.2.3. Understand the AWS Services

Before deploying the system, we need to understand the primary services used in the network automation and monitoring architecture.

AWS Service Purpose
Amazon VPC Creates an isolated virtual network
Amazon EC2 Provides virtual servers for testing
AWS IAM Manages identities and permissions
VPC Flow Logs Captures network traffic metadata
Amazon CloudWatch Collects and analyzes logs and metrics
Amazon SNS Sends monitoring notifications
AWS Systems Manager Helps manage and access EC2 instances
Elastic Load Balancing Distributes incoming application traffic
EC2 Auto Scaling Automatically adjusts EC2 capacity

These services work together to provide a cloud environment capable of collecting network logs, monitoring network activity, detecting specified events, and sending alerts.

The detailed configuration of these services will be introduced in the following sections.

5.2.4. Check AWS IAM Permissions

AWS Identity and Access Management (IAM) is a service that allows administrators to securely control access to AWS resources.

IAM helps determine which users, roles, and services are allowed to perform specific actions.

Step 1: Open the IAM Console

  1. Go to the AWS Management Console.
  2. Locate the search bar at the top of the page.
  3. Type IAM.
  4. Select IAM from the search results.
  5. Wait for the IAM Dashboard to appear.

Figure 5.2.5. AWS IAM Dashboard.

Step 2: Check IAM Access

In the IAM Console, review the following sections:

  • Users: Manage IAM users.
  • User groups: Organize users into groups.
  • Roles: Define permissions that AWS services or identities can assume.
  • Policies: Define allowed and denied actions.

For this workshop, the working identity needs appropriate permissions to manage:

  • Amazon VPC and network resources.
  • Amazon EC2 instances.
  • IAM roles and policies required by the workshop.
  • Amazon CloudWatch Logs and Alarms.
  • VPC Flow Logs.
  • Amazon SNS topics and subscriptions.
  • AWS Systems Manager resources.

Use the principle of least privilege, granting only the permissions necessary to complete the workshop.

Avoid using the AWS root user for daily operations. Enable multi-factor authentication (MFA) to improve account security.

Figure 5.2.6. Checking IAM access and permissions.

Note: You do not need to create new IAM roles at this stage. Required service roles will be configured during the deployment and monitoring sections.

5.2.5. Prepare the Amazon VPC Environment

Amazon Virtual Private Cloud (VPC) enables users to create an isolated virtual network within AWS.

In this workshop, Amazon VPC will provide the network infrastructure for the EC2 instance and monitoring services.

Step 1: Open the VPC Console

  1. Return to the AWS Management Console.
  2. Enter VPC in the search bar.
  3. Select the VPC service.
  4. Locate Your VPCs in the left navigation menu.
  5. Click Your VPCs.

The console displays the VPCs currently available in the selected Region.

Figure 5.2.7. Amazon VPC management interface.

Step 2: Explore VPC Components

In the left navigation menu, locate the following components:

1. Your VPCs

Displays existing virtual private networks.

2. Subnets

Allows users to divide a VPC into smaller network segments.

3. Route Tables

Defines how network traffic is routed between subnets and other destinations.

4. Internet Gateways

Provides a connection between a VPC and the Internet when routing and access settings permit it.

5. Security Groups

Controls allowed inbound and outbound traffic for associated resources.

6. Flow Logs

Captures metadata about network traffic passing through network interfaces.

At this stage, we only need to become familiar with these components.

The actual VPC, subnet, route table, and security group configuration will be performed in Section 5.3: Network and EC2 Deployment.

5.2.6. Prepare the Amazon EC2 Environment

Amazon Elastic Compute Cloud (EC2) provides scalable virtual computing resources in the AWS Cloud.

In this workshop, an EC2 instance will serve as a test server for network connectivity and traffic monitoring.

Step 1: Open the EC2 Console

  1. Return to the AWS Management Console.
  2. Search for EC2.
  3. Select the EC2 service.
  4. In the left navigation menu, click Instances.
  5. Review the list of existing instances.

Figure 5.2.8. Amazon EC2 Instances interface.

Step 2: Check the EC2 Deployment Environment

Before launching an instance, check the following information:

  • The selected AWS Region.
  • Available EC2 instance types.
  • Available Amazon Machine Images (AMIs).
  • Instance quotas and account eligibility.
  • Permissions to launch EC2 instances.
  • AWS Systems Manager access requirements.

For this workshop, we plan to use an Amazon Linux instance to generate test traffic and verify network monitoring.

The instance type will be selected based on the available resources and cost considerations.

Important: Do not launch an EC2 instance yet. The virtual network must be configured first.

The EC2 instance will be created in Section 5.3.

5.2.7. Prepare Amazon CloudWatch

Amazon CloudWatch is a monitoring and observability service that provides information about AWS resources, applications, and system performance.

In this workshop, CloudWatch will be responsible for collecting, analyzing, and displaying network monitoring information.

Step 1: Open Amazon CloudWatch

  1. Sign in to the AWS Management Console.
  2. Search for CloudWatch.
  3. Select CloudWatch.
  4. Wait for the CloudWatch console to load.
  5. Explore the navigation menu.

Figure 5.2.9. Amazon CloudWatch overview.

Step 2: Explore Monitoring Features

The following features will be used throughout the workshop:

CloudWatch Logs

Stores and manages log data collected from AWS resources.

CloudWatch Metrics

Provides numerical measurements used to monitor system performance and events.

CloudWatch Alarms

Monitors metrics and changes alarm states when predefined conditions are met.

CloudWatch Dashboards

Displays monitoring information in a centralized visual interface.

During deployment, VPC Flow Logs will be configured to send traffic metadata to CloudWatch Logs.

We will then create metric filters and alarms to detect rejected network traffic.

For example, the workshop will monitor rejected TCP traffic on port 8080.

A metric filter can identify matching log events, while CloudWatch Alarms can monitor the resulting metric.

Note: No log groups or alarms need to be created in this preparation section.

These configurations will be covered in Section 5.4: Monitoring Configuration.

5.2.8. Prepare Amazon SNS

Amazon Simple Notification Service (SNS) is a managed messaging service that enables notifications to be sent to subscribed endpoints.

In this workshop, Amazon SNS will be integrated with CloudWatch Alarms to deliver email notifications when monitoring conditions are triggered.

Step 1: Open the Amazon SNS Console

  1. Return to the AWS Management Console.
  2. Search for SNS.
  3. Select Simple Notification Service.
  4. Open the SNS console.
  5. Locate Topics and Subscriptions in the navigation menu.

Figure 5.2.10. Amazon SNS management interface.

Step 2: Understand SNS Components

SNS Topic

A communication channel used to publish messages to subscribers.

SNS Subscription

Connects a subscriber, such as an email address, to an SNS topic.

When the monitoring system detects an event that causes a CloudWatch Alarm to change state, the alarm can publish a notification to an SNS topic.

Amazon SNS then sends the notification to confirmed subscribers.

For this workshop, email will be used as the notification method.

The SNS topic and email subscription will be configured in the monitoring workflow.

5.2.9. Configure AWS Budgets

Monitoring AWS costs is an important part of working with cloud infrastructure.

Some AWS resources, including EC2 instances, CloudWatch Logs, load balancers, and network services, may generate charges depending on usage and account eligibility.

AWS Budgets allows users to define spending thresholds and receive notifications when costs approach or exceed those thresholds.

Step 1: Open AWS Billing

  1. Go to the AWS Management Console.
  2. Search for Billing and Cost Management.
  3. Open the Billing console.
  4. Locate Budgets in the navigation menu.
  5. Click Budgets.

Step 2: Create a Cost Budget

  1. Click Create budget.
  2. Choose Cost budget or an appropriate cost-budget template.
  3. Select Monthly as the budget period.
  4. Enter a budget amount based on your requirements.
  5. Configure notification thresholds.
  6. Enter an email address for alerts.
  7. Review the budget configuration.
  8. Click Create budget.

For example, you can set a monthly budget of 5 USD as an initial monitoring threshold.

This amount is only an example and does not guarantee that the workshop will cost less than 5 USD.

Figure 5.2.11. Configuring AWS Budgets for cost monitoring.

Important: AWS Budgets does not automatically stop all running resources when a spending threshold is reached. Cost reporting and notifications may also be delayed.

Always review resource pricing and delete unused resources after completing the workshop.

After completing this preparation section, you should have:

  • Successfully accessed the AWS Management Console.
  • Selected the Asia Pacific (Singapore) Region.
  • Understood the main AWS services used in the workshop.
  • Checked the necessary IAM permissions.
  • Explored the VPC and EC2 management interfaces.
  • Accessed CloudWatch and SNS.
  • Configured cost monitoring through AWS Budgets.
  • Prepared the AWS environment for network deployment.

Conclusion

In this section, we completed the preparation steps required to build a network automation and monitoring system on AWS.

We became familiar with the AWS Management Console, selected the deployment Region, reviewed the essential services, and checked the permissions and cost monitoring settings.

These preparations provide the foundation for deploying a virtual network and configuring monitoring capabilities in the following sections.

In the next section, 5.3. Network and EC2 Deployment, we will create and configure the core network infrastructure, including:

  • Amazon VPC
  • Public Subnet
  • Internet Gateway
  • Route Table
  • Security Group
  • Amazon EC2 Instance

After deploying these resources, we will test network connectivity and prepare the infrastructure for VPC Flow Logs and CloudWatch monitoring.
