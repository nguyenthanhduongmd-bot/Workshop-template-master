Triển khai mạng và EC2

1. Mục tiêu

Phần này hướng dẫn tạo hạ tầng mạng và cấu hình EC2 để tự động cài đặt Nginx bằng User data.

Các công việc gồm:

  1. Tạo VPC, public subnet và private subnet.
  2. Kiểm tra route table và Internet Gateway.
  3. Tạo Security Group cho phép HTTP từ IP máy thực hành.
  4. Cấu hình EC2 và mã hóa ổ đĩa EBS.
  5. Nhập User data để tự động cài đặt Nginx.
  6. Khởi tạo EC2 và ghi lại thông tin phục vụ giám sát.

Lần triển khai trong các ảnh sử dụng United States (N. Virginia) — us-east-1. Ảnh cấu hình EC2 hiển thị AMI Canonical Ubuntu 26.04.

Thống nhất Region: Nếu tiếp tục triển khai theo các ảnh này, cập nhật Region trong phần 5.1, 5.2 và cấu hình giám sát ở phần 5.4 thành us-east-1. Các điều kiện aws:RequestedRegion và ARN có chứa Region trong policy cũng cần được điều chỉnh tương ứng. Việc sửa Markdown không thay đổi tài nguyên hoặc quyền trên AWS.

Thành phần Cấu hình

3. Tạo VPC và subnet

Nếu VPC workshop đã được tạo đúng cấu hình, mở lại để kiểm tra và tiếp tục sang mục 4.

  1. Mở dịch vụ VPC.
  2. Kiểm tra Region đang là United States (N. Virginia).
  3. Chọn Create VPC.
  4. Trong Resources to create, chọn VPC and more.
  5. Bật Name tag auto-generation và nhập tiền tố aws-network-workshop.
  6. Cấu hình theo bảng:
Trường Giá trị
IPv4 CIDR block 10.10.0.0/16
IPv6 CIDR block Không sử dụng
Tenancy Default
Number of Availability Zones 1
Number of public subnets 1
Number of private subnets 1
NAT gateways None
VPC endpoints None
Enable DNS resolution Bật
Enable DNS hostnames Bật
  1. Tại khu vực cấu hình subnet, mở Customize subnets CIDR blocks.
  2. Nhập:
Subnet IPv4 CIDR
Public subnet 10.10.1.0/24
Private subnet 10.10.2.0/24
  1. Kiểm tra phần Preview.
  2. Chọn Create VPC và chờ hoàn tất.

Public subnet được sử dụng để đặt EC2 chạy Nginx. Private subnet minh họa việc phân tách mạng và chưa chứa EC2 trong bài thực hành này.

4. Kiểm tra public subnet

  1. Mở VPC → Subnets.
  2. Chọn public subnet của workshop.
  3. Kiểm tra CIDR, trạng thái, Availability Zone, VPC và route table.

Trong ảnh có thể xác nhận:

Thông tin Giá trị hiển thị
IPv4 CIDR 10.10.1.0/24
State Available
Availability Zone us-east-1a
VPC aws-network-workshop-vpc
Route table aws-network-workshop-rtb-public
Auto-assign public IPv4 address No

Ghi lại VPC ID và Public subnet ID để sử dụng khi tạo EC2.

Mục Auto-assign public IPv4 address đang là No. Khi tạo EC2, chọn Auto-assign public IP → Enable để cấp public IPv4 cho instance.

Ảnh này thể hiện thông tin subnet và liên kết tới route table. Các route bên trong bảng định tuyến được kiểm tra ở mục tiếp theo.

5. Kiểm tra route table

5.1. Public route table

  1. Từ trang thông tin subnet ở ảnh 1, tìm mục Route table.
  2. Nhấn liên kết màu xanh của aws-network-workshop-rtb-public.
  3. Mở tab Routes.
  4. Đối chiếu các route cần có:
Destination Target
10.10.0.0/16 local
0.0.0.0/0 Internet Gateway có ID bắt đầu bằng igw-

igw-... là ký hiệu minh họa. Trên AWS Console cần chọn đúng Internet Gateway thuộc VPC workshop.

Nếu thiếu default route:

  1. Chọn Edit routes.
  2. Chọn Add route.
  3. Nhập Destination là 0.0.0.0/0.
  4. Trong Target, chọn Internet Gateway.
  5. Chọn Internet Gateway của VPC workshop.
  6. Nhấn Save changes.

Mở tab Subnet associations để kiểm tra public subnet sử dụng đúng bảng định tuyến.

5.2. Private route table

  1. Mở VPC → Subnets.
  2. Chọn private subnet có CIDR 10.10.2.0/24.
  3. Mở tab Route table.
  4. Kiểm tra route nội bộ:
Destination Target
10.10.0.0/16 local

Theo cấu hình của bài, private subnet không có default route tới Internet Gateway hoặc NAT Gateway.

6. Tạo Security Group

6.1. Nhập thông tin Security Group

  1. Mở EC2 → Security Groups.
  2. Chọn Create security group.
  3. Điền:
Trường Giá trị
Security group name aws-network-workshop-web-sg
Description HTTP access from workshop client
VPC VPC workshop

6.2. Cấu hình inbound rule

Trong Inbound rules, chọn Add rule và đặt Type → HTTP.

Trong ảnh:

  • Type đã chọn HTTP.
  • Protocol là TCP.
  • Port range là 80.
  • Source type đang là Custom.
  • Ô Source chưa được điền.

Hoàn thiện nguồn truy cập như sau:

  1. Nhấn ra vùng trống để đóng danh sách gợi ý đang mở trong ô Source.
  2. Nhấn mũi tên tại ô Source type, đang hiển thị Custom.
  3. Chọn My IP.
  4. Kiểm tra AWS tự điền IP công cộng của máy thực hành, dạng x.x.x.x/32.

Rule inbound cần lưu:

Type Protocol Port range Source
HTTP TCP 80 IP công cộng của máy thực hành /32

Giữ cổng 8080 chưa được cho phép để tạo lưu lượng REJECT ở phần kiểm thử. Bài này chưa cần rule SSH cổng 22.

6.3. Kiểm tra outbound và lưu

  1. Kiểm tra outbound IPv4 cho phép All traffic → 0.0.0.0/0 để EC2 tải gói cài đặt.
  2. Chọn Create security group.
  3. Mở lại Security Group vừa tạo.
  4. Trong tab Inbound rules, xác nhận rule HTTP 80 có Source là IP máy thực hành /32.
  5. Ghi lại Source IP để đối chiếu Flow Logs ở phần sau.

7. Cấu hình EC2

7.1. Chọn AMI và instance type

  1. Mở EC2 → Instances → Launch instances.
  2. Cấu hình:
Mục Giá trị
Name aws-network-workshop-web
AMI theo ảnh thực hành Canonical Ubuntu 26.04
Architecture amd64 / x86_64
Instance type t3.micro
Key pair Proceed without a key pair
Number of instances 1

Ô Number of instances nằm trong khung Summary ở bên phải trang launch.

7.2. Cấu hình Network settings

Trong Network settings, nhấn Edit và chọn:

Mục Giá trị
VPC VPC workshop
Subnet Public subnet 10.10.1.0/24
Auto-assign public IP Enable
Firewall Select existing security group
Security Group aws-network-workshop-web-sg

7.3. Cấu hình storage

Trong ảnh có thể xác nhận:

Thông tin Giá trị hiển thị
Region United States (N. Virginia)
AMI Canonical Ubuntu 26.04
Instance type t3.micro
Number of instances 1
Security Group aws-network-workshop-web-sg
Root volume 8 GiB
Volume type gp3
Encryption Not encrypted

7.4. Bật mã hóa root volume

Thực hiện trước khi launch:

  1. Trong khung Configure storage, nhấn Advanced màu xanh ở góc trên bên phải.
  2. Mở phần cấu hình root volume nếu đang thu gọn.
  3. Tìm mục Encrypted hoặc Encryption.
  4. Chuyển từ Not encrypted sang Encrypted / Yes.
  5. Nếu được yêu cầu chọn khóa KMS, sử dụng khóa EBS mặc định aws/ebs.
  6. Kiểm tra Delete on termination đã bật.
  7. Xác nhận cấu hình cuối hiển thị Encrypted.

Ảnh 3 ghi nhận thời điểm ổ đĩa chưa mã hóa. Cần chụp thêm ảnh sau khi bật Encrypted để minh chứng cấu hình cuối.

Nếu thay đổi AMI, kiểm tra lại các thiết lập mạng và storage trước khi launch.

8. Cài Nginx tự động bằng User data

8.1. Mở Advanced details

Kéo xuống và mở Advanced details.

Cấu hình:

Mục Giá trị
IAM instance profile Để trống
Detailed CloudWatch monitoring Giữ tắt, sử dụng basic monitoring
Metadata version V2 only / token required nếu hiển thị

Role workshop-flowlogs-role được cấu hình cho Flow Log ở phần 5.4.

8.2. Nhập script

Trong ô User data, dán toàn bộ script sau:

#!/bin/bash
set -euxo pipefail
export DEBIAN_FRONTEND=noninteractive

apt-get -o Acquire::Retries=3 update
apt-get -o Acquire::Retries=3 -o DPkg::Lock::Timeout=120 install -y nginx

cat > /var/www/html/index.html <<'HTML'
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>AWS Network Workshop</title>
</head>
<body>
  <h1>AWS Network Workshop</h1>
  <p>Nginx is running.</p>
</body>
</html>
HTML

systemctl enable --now nginx

Script thực hiện:

  1. Cập nhật danh sách gói.
  2. Cài đặt Nginx.
  3. Tạo trang HTML phục vụ kiểm thử.
  4. Bật dịch vụ Nginx.

Để ô User data has already been base64 encoded ở trạng thái chưa chọn.

Nhập User data trước khi launch. Kết quả cài đặt và khả năng truy cập website cần được kiểm tra ở phần 5.5.

9. Launch và kiểm tra EC2

9.1. Kiểm tra trước khi launch

Đối chiếu:

  • Number of instances là 1.
  • Đã chọn đúng AMI và instance type t3.micro.
  • EC2 nằm trong public subnet.
  • Auto-assign public IP đã bật.
  • Đã chọn đúng Security Group.
  • Root volume là 8 GiB, loại gp3.
  • Root volume đã bật mã hóa.
  • Đã nhập đầy đủ User data.

Sau đó nhấn Launch instance.

9.2. Kiểm tra sau khi launch

  1. Chọn View all instances.
  2. Mở instance aws-network-workshop-web.
  3. Chờ trạng thái Running và các status checks đều đạt.
  4. Trong Details, kiểm tra VPC, subnet, public IPv4 và private IPv4.
  5. Trong Security, kiểm tra Security Group và rule đã lưu.
  6. Trong Storage, ghi lại Root Volume ID và kiểm tra thông tin mã hóa.

Ghi thông tin thực tế vào bảng:

Thông tin Giá trị thực tế
Region us-east-1
VPC ID Điền từ AWS Console
Public subnet ID Điền từ AWS Console
Instance ID Bổ sung sau khi launch
Public IPv4 của EC2 Bổ sung sau khi launch
Private IPv4 của EC2 Bổ sung sau khi launch
Public IP máy thực hành Ghi từ Source My IP của rule đã lưu
Root EBS Volume ID Bổ sung từ tab Storage

Trạng thái Running chưa xác nhận Nginx đã phục vụ HTTP thành công. Kết quả website được kiểm tra trong phần 5.5.

11. Kiểm tra hoàn thành

Chỉ đánh dấu sau khi kiểm tra được kết quả trên AWS:

  • VPC và hai subnet có đúng CIDR.
  • Public route table có default route tới Internet Gateway.
  • Private subnet sử dụng đúng route table.
  • Rule HTTP 80 đã lưu với Source là IP máy thực hành /32.
  • Cổng 8080 vẫn chưa được cho phép.
  • Root volume đã bật mã hóa và Delete on termination.
  • User data đã được nhập trước khi launch.
  • EC2 Running, status checks đạt và có public IPv4.
  • Đã lưu ID tài nguyên và các địa chỉ IP.
  • Đã bổ sung ảnh của các cấu hình đã lưu và EC2 thực tế.

Sau khi hoàn thành, tiếp tục 5.4 — Cấu hình giám sát trong Region us-east-1.

Giữ tài nguyên cho các phần kiểm thử và thực hiện dọn tài nguyên ở phần 5.9 sau khi lưu đủ minh chứng.
